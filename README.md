## 1. Objective

In this practical assignment, you will learn how to create automated user interface tests. You will not only check whether a web page opens, but also simulate user actions and verify that the application behaves as expected.

By the end of this assignment, you will be able to:
- explain what UI testing means;
- open a GitHub project in the Codespaces environment;
- use Playwright to open and control a web application;
- locate web page elements using locators;
- perform user actions, such as entering text, pressing a key, and checking a checkbox;
- verify the actual result using `expect()`;
- run tests and analyze test results.

### What is UI testing?

UI (User Interface) means the user interface—the part of a web application that users see and interact with.

A UI test checks, for example:
- whether a user can fill in a form;
- whether clicking a button triggers the correct action;
- whether a new task appears in the list;
- whether deleting a task works;
- whether the correct result or error message is displayed to the user.

**The purpose of an automated UI test:** a program performs actions on a web page on behalf of a user and checks whether the result matches the expected outcome.

## 6. Playwright Fundamentals

Open the `tests/todo.spec.js` file. Before writing tests, familiarize yourself with the following concepts.

### `test()`

`test()` defines a single test case. The test name describes what is being checked.

```javascript
test('the user can add a task', async ({ page }) => {
  // Write the test steps here.
});
```

### `page`

`page` represents the browser page that the test interacts with.

Opening a web page:

```javascript
await page.goto('https://demo.playwright.dev/todomvc/');
```

### Locators (`locator`)

A locator helps find an element on a web page, such as a text field, button, or checkbox.

Examples:

```javascript
page.getByPlaceholder('What needs to be done?');
page.getByText('My task');
page.getByRole('button');
page.getByRole('checkbox');
```

### Simulating user actions

```javascript
await input.fill('My task');       // enters text
await input.press('Enter');        // presses the Enter key
await checkbox.check();            // checks the checkbox
await button.click();               // clicks the button
await element.hover();              // moves the mouse over the element
```

### `expect()`

`expect()` is used to check whether the actual result matches the expected result.

```javascript
await expect(page.getByText('My task')).toBeVisible();
```

Common assertions:

```javascript
await expect(element).toBeVisible();    // the element is visible
await expect(element).toBeHidden();     // the element is not visible
await expect(checkbox).toBeChecked();   // the checkbox is checked
await expect(element).toHaveCount(1);   // one element is found
```

### Why is `await` used?

Playwright actions take time: the browser opens a page, finds an element, or performs a click. `await` tells JavaScript to wait until the previous action has finished before moving on to the next step.

## 7. Test 1 – Adding a Task (Completed Example)

The first test is already complete in the `tests/todo.spec.js` file. Your task is to read through it, run it, and understand what each line does.

```javascript
const { test, expect } = require('@playwright/test');

test('the user can add a task', async ({ page }) => {
  await page.goto('https://demo.playwright.dev/todomvc/');

  const input = page.getByPlaceholder('What needs to be done?');
  await input.fill('Learn UI testing');
  await input.press('Enter');

  await expect(page.getByText('Learn UI testing')).toBeVisible();
});
```

### Code explanation

1. `require('@playwright/test')` imports Playwright's testing functions.
2. `test()` starts a new test case.
3. `page.goto()` opens the web page being tested.
4. `getByPlaceholder()` finds the text field using its placeholder text.
5. `fill()` enters the task name into the text field.
6. `press('Enter')` presses the Enter key.
7. `expect(...).toBeVisible()` checks whether the added task is visible on the web page.

**Think about it:** What would be the expected result of this test? What would happen if the application did not add the task to the list?

## 10. Running the Tests

Run all tests:

```bash
npx playwright test
```

Run tests with the browser window visible:

```bash
npx playwright test --headed
```

Run one specific test by name:

```bash
npx playwright test -g "the user can add a task"
```

View the test results in an HTML report:

```bash
npx playwright show-report
```

### How to read the results

- `passed` – the test passed successfully.
- `failed` – the test failed.
- `skipped` – the test was skipped.

If a test fails, read the error message displayed in the terminal. Check whether:
- the web page opened;
- the locator found the correct element;
- the action was performed in the correct order;
- the expected result was defined correctly.

**Important:** a failed test does not automatically mean that there is a bug in the web application. The problem may also be in the test code or in an incorrect test assumption.

## 11. Common Problems and Solutions

### `npm: command not found`

Node.js or npm is not available in the development environment. Make sure you are using GitHub Codespaces and try opening the terminal again.

### `Cannot find module '@playwright/test'`

The dependencies have not been installed. Run:

```bash
npm install
```

### Playwright cannot find the browser

Install Chromium:

```bash
npx playwright install chromium
```

### The test cannot find an element

Check:
- whether you are using the correct text or placeholder;
- whether the element is present on the page;
- whether you are using the correct locator;
- whether the previous action has finished.

### The test fails, but the web page seems to work

Check the test step by step. Compare the expected result with the actual result. If necessary, run the test again and examine the error message.
